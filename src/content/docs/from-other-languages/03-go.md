# Go 개발자를 위한 Zig 가이드

Go와 Zig은 **"단순함과 가독성", "빠른 컴파일", "외부 의존성 없는 단일 실행 바이너리 생성"**이라는 개발자 경험(DX) 철학을 깊이 공유합니다.

하지만 Go가 런타임 가비지 컬렉터(GC)와 그린 스레드(Goroutine) 런타임을 내장한 응용 계층 언어라면, Zig은 **런타임이 전혀 없는 순수 시스템 프로그래밍 언어**로서 마이크로초 단위의 지연 시간(Low-latency)과 극도의 메모리 효율을 제공합니다.

---

## 📌 핵심 멘탈 모델 매핑

| Go 개념 | Zig 대응 개념 | 핵심 차이점 |
|---|---|---|
| 가비지 컬렉터 (GC) | `std.mem.Allocator` | 런타임 GC 일시정지(STW) 없음. 수동/Arena 기반 메모리 관리 |
| `if err != nil` | `try` / `catch` / `errdefer` | 반복적인 에러 체크 구문 축약, 트랜잭션 롤백 보장 |
| `goroutine` & `chan` | `std.Thread` & 링 버퍼/큐 | OS 네이티브 스레드 활용 (런타임 스케줄러 오버헤드 없음) |
| 슬라이스 (`[]T`) | 슬라이스 (`[]T`) | 포인터와 길이(`len`)를 가지는 구조가 거의 동일 |
| `defer` 구문 | `defer` & `errdefer` | Go의 `defer`는 함수 종료 시 실행되지만, Zig의 `defer`는 **현재 블록 스코프(`{}`)** 탈출 시 실행 |
| 빈 인터페이스 `any` | `anyopaque` (포인터) / `comptime` | 런타임 인터페이스 박싱 오버헤드 없이 정적 타입 검사 |
| `go build` 크로스 컴파일 | `zig build -Dtarget=...` | Cgo 컴파일러까지 완벽히 내장된 무결점 크로스 컴파일 |

## 1. 에러 처리: `if err != nil` vs `try`

Go 개발자가 가장 익숙한 에러 처리 패턴을 Zig에서는 더 간결하게 표현합니다.

### Go 코드
```go
val, err := parseValue(input)
if err != nil {
    return nil, err
}
```

### Zig 코드
```zig
const std = @import("std");

fn parseValue(input: []const u8) !u32 {
    // try는 if err != nil { return err } 과 정확히 같습니다
    const val = try std.fmt.parseInt(u32, input, 10);
    return val;
}

test "try vs if err != nil" {
    const res = try parseValue("123");
    try std.testing.expectEqual(@as(u32, 123), res);
}
```

## 2. `defer` 스코프의 결정적 차이

Go의 `defer`는 **함수(Function) 단위**로 지연 실행되지만, Zig의 `defer`는 **중괄호 블록(Block Scope `{}`)**을 벗어나는 즉시 실행됩니다.

```zig
const std = @import("std");

test "zig block-scoped defer" {
    var step: u32 = 0;

    {
        defer step += 10;
        step += 1;
    } // <-- 여기서 defer가 즉시 실행됨!

    try std.testing.expectEqual(@as(u32, 11), step);
}
```

## 3. Go의 Cgo 대체하기

Go에서 C 라이브러리를 쓰려면 Cgo 설정과 크로스 컴파일 복잡성이 커지지만, Zig은 Cgo보다 훨씬 자연스럽고 빠르게 C 코드를 연동합니다.

```zig
const std = @import("std");

// C 헤더 즉시 임포트
const c = @cImport({
    @cInclude("math.h");
});

test "c math library call" {
    const result = c.sqrt(16.0);
    try std.testing.expectEqual(@as(f64, 4.0), result);
}
```
